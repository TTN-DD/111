第 17 讲 17-2.html fetch / async / 异常处理

一次真实的接口请求有三种结局：成功、HTTP 报错、网络断掉。fetch 只有后两种才会走 catch—— 404 和 500 不会抛异常，必须自己检查 res.ok。这是最容易漏的一步。

一、请求一份用户列表

数据源是公开的 JSONPlaceholder。如果外网不通，会自动降级到内置演示数据，并在状态栏标注。

点"加载数据"开始。
async function load() {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/users");
    if (!res.ok) throw new Error("HTTP " + res.status);   // 关键：4xx/5xx 不会自动抛错
    const data = await res.json();
    render(data);
  } catch (err) {
    showError(err.message);   // 网络断掉才会走到这里
  }
}
情况res.ok会不会进 catch怎么处理
200 正常true不会直接 res.json()
404 地址错了false不会手动判断 res.ok 后抛错
500 服务端挂了false不会同上
断网 / DNS 失败—会catch 里提示"网络异常"
响应不是 JSONtrue会（res.json() 抛）catch 里提示"数据格式错误"
三个必备细节： ① if (!res.ok) throw ... 一定要写，否则 404 会当成成功数据往下传； ② 请求期间把按钮 disabled = true，避免用户连点发出重复请求； ③ 无论如何都要给"空状态"和"错误状态"设计好界面，不能只在成功时才有东西可看。
