Canvas 粒子网络动画

第 18 讲 18-1.html Canvas + requestAnimationFrame

六十个粒子在画布上漂移，距离小于阈值就连一条线，鼠标靠近时被推开。 没有引入任何库，全部是 canvas.getContext("2d") 的直线和圆弧——这个效果几乎所有"科技感"页面都在用。

-- fps -- 粒子 移动鼠标试试

核心循环只有三步

清空画布 → 计算新位置 → 画出来，每秒重复 60 次。

function frame(now) {
  ctx.clearRect(0, 0, W, H);      // 1. 擦掉上一帧
  for (const p of dots) {         // 2. 更新位置 + 画圆
    p.x += p.vx; p.y += p.vy;
    ctx.beginPath();
    ctx.arc(p.x, p.y, 1.6, 0, Math.PI * 2);
    ctx.fill();
  }
  drawLines();                    // 3. 画连线
  requestAnimationFrame(frame);   // 下一帧再叫我
}
requestAnimationFrame(frame);
关键点为什么这么做
requestAnimationFrame 而不是 setInterval跟着屏幕刷新率走，页面切到后台会自动暂停，省电；setInterval 会一直跑
连线距离用平方比较dx*dx + dy*dy < d*d 避免每次开根号，60 个粒子每帧要算 1770 对
透明度按距离衰减近的线深、远的线浅，视觉上才有"网络"的层次感
监听 resize 并乘 devicePixelRatio否则高分屏上会糊，图元坐标要跟着缩放
尊重 prefers-reduced-motion系统开了"减少动态效果"就只画静态一帧
性能红线：连线是 O(n²)，60 个粒子是 1770 次比较，140 个就是 9730 次——还能跑。 如果粒子数是几百上千，就必须改用空间网格分桶（把画布切成格子，只比较相邻格子里的粒子）， 否则帧率会掉到个位数。
