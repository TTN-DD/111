层叠与继承

第 5 讲 5.html CSS 核心机制

「层叠」解决的是多条规则同时命中一个元素时谁生效；「继承」解决的是子元素没写样式时要不要听父元素的。 这两条是 CSS 的地基，调不出效果的九成原因都在这。

一、优先级怎么算

把选择器拆成四位数字比较，从左往右逐位比，不是加总。

选择器行内idclass / 属性 / 伪类标签 / 伪元素合计
p00010,0,0,1
.card p00110,0,1,1
#main .card p01110,1,1,1
style="color:red"10001,0,0,0

注意 0,0,1,1 和 0,0,2,0：后者更大。 不要误以为"class 数量乘以 10 加起来"——虽然多数情况下结果巧合一致，但十一位的 class 也压不过一个 id。

二、同权重：后写的覆盖先写的

两个类权重都是 0,0,1,0，谁在后面谁生效。

我同时有 first 和 second 两个类，最终是 second 的颜色
.first  { background: #eaf1fe; color: #1c4fc0; }
.second { background: #eef8f3; color: #12603f; }  /* 在后面，赢 */

三、哪些属性会继承

父元素设了字体、颜色、行高，子元素不写也自动获得。

父元素：紫色文字、衬线字体、字间距 0.02em。
子元素没有写 color 和 font-family，但文字变成了紫色衬线体——这就是继承。
反过来，子元素有自己的灰色边框和白色背景，说明 border 和 background 不会继承。
会继承（文字相关）不会继承（盒子和背景）
color font-* line-heightmargin padding border
letter-spacing text-alignbackground width height
visibility cursordisplay position overflow

四、想让不继承的属性也继承：用 inherit

中间那个子盒子写了 border-color: inherit，于是拿到了父元素的蓝色边框。

父元素边框：蓝色
没写 inherit：保留自己的橙色边框
写了 border-color: inherit：边框变成父元素的蓝色

五、!important 的代价

下面这段文字有两条同名规则，后面那条加了 !important，于是先写的反而赢了。

我是红色，因为 .imp strong 那条后面加了 !important，把后面写的蓝色盖掉了。 
.imp strong { color: #8a2b2b !important; }
.imp strong { color: #1c4fc0; }             /* 明明在后面，却输了 */

这就是 !important 最危险的地方：它破坏了"后写覆盖先写"这个直觉， 后来接手的人看到颜色不对，改哪一条都没用，得全局搜 !important。 只在覆盖第三方库、或者真的没法改源码时才用。

排查顺序（实测有效）： ① 打开开发者工具看这条属性有没有被划掉，划掉说明被更高优先级覆盖； ② 看继承来的值（Computed 面板会标「inherited from」）； ③ 还是没有？检查有没有 !important、有没有内联 style； ④ 顺序错了？看两个规则谁在后面。
