Canvas 绘制系统架构图

第 18 讲 18-2.html 五层架构 · 可导出 PNG

整张图没有一个 div：五层、十八个节点、所有连线都是 Canvas 画的。 鼠标悬停能看到节点说明（自己做命中检测），右下角可以导出 PNG——这两件事用图片做都做不到。

鼠标移到方块上查看说明

数据结构决定代码量

节点是数组，连线是"谁指向谁"的 id 对，画图就是两层循环。

const NODES = [
  { id: "web", label: "Web 前端", x: 90,  y: 60,  desc: "…" },
  { id: "cdn", label: "CDN",       x: 90,  y: 160, desc: "…" },
  // …
];
const LINKS = [["web","cdn"], ["app","cdn"], ["cdn","gateway"]];

NODES.forEach(drawBox);                     // 先画方块
LINKS.forEach(([a, b]) => drawArrow(byId(a), byId(b)));  // 再画箭头

改架构图只需要改这两个数组，不用动绘制代码——这是"用代码画图"和"截图贴图"最大的区别。

要点做法
圆角矩形Canvas 没有现成 API，用 arcTo 或四段 quadraticCurveTo 自己封一个
命中检测把鼠标坐标换算回画布坐标，逐个判断是否落在矩形内（倒序判断，上层优先）
文字居中textAlign="center" + textBaseline="middle"，位置用矩形中心点
高分屏清晰canvas 的 width 属性乘 devicePixelRatio，CSS 尺寸保持不变
导出图片canvas.toDataURL("image/png") + <a download> 触发下载
什么该用 Canvas、什么该用 SVG：节点数量固定、需要"图元级交互"（悬停、拖拽、导出图片）→ Canvas； 需要文字可选中、可被搜索引擎读、要加 <a> 链接 → SVG。 架构图如果只在页面里展示，其实 SVG 更合适；用 Canvas 是为了练习"自己画"。
