Promise 与 async / await

第 17 讲 17-4.html 串行 vs 并行

三个"接口"分别要 900ms、600ms、1200ms。同样的三个任务， 串行 await 要等 2.7 秒，并行 Promise.all 只要 1.2 秒。 这一页就是让你亲眼看到这个差别——它是真实项目里最容易优化的性能点。

两种写法对照

同一份任务，差别只在"等不等前一个完成"。

串行：总耗时 = 累加

const a = await checkStock();   // 900ms
const b = await calcFreight();  // 600ms
const c = await createOrder();  // 1200ms
// 合计 ≈ 2700ms

并行：总耗时 = 最慢的那个

const [a, b, c] = await Promise.all([
  checkStock(), calcFreight(), createOrder()
]);
// 合计 ≈ 1200ms

并行的前提是任务之间没有依赖。如果"下单"必须先拿到"库存结果"，那就只能串行—— 把没有依赖的请求排成队，是最常见的性能浪费。

错误处理也要知道差别：Promise.all 只要有一个失败就整体失败（快速失败）， 适合"全都必须成功"的场景；Promise.allSettled 会等全部结束并返回每一项的状态， 适合"部分失败也能接受"的场景（比如页面里同时挂三个互不相关的模块）。
